# 2026-11-11 启动加速：缓存秒开 + 增量同步

## 主题

打开软件要等「正在打开…」很久（每次 refresh 要串行跑 5 个网络请求），改为**本地缓存秒开 + 只拉变化数据**，消除启动卡顿。

## 问题

- `loadData()` 每次串行跑：`auth.getUser` → `family_member` → `family` → `baby` + `event`（并行两张表），共 5 次网络往返。
- 启动时 `booting` 阻塞式等全部拉完才渲染；回到页面 / 25 秒轮询 / Realtime 变更都触发整轮 `refresh`，全量拉 500 条事件。
- 老人手机弱网时，每次打开都白屏等很久。

## 方案

1. **缓存秒开**（`src/lib/cache.ts`）：localStorage 存云端数据快照（宝宝 + 最近 500 条事件 + 同步游标 + 墓碑）。启动先读快照渲染，后台静默同步，不再白屏等待。
2. **增量同步**：`refresh` 走 `updated_at > 游标` 只拉变化行（重叠 3 秒吸收时钟偏差），合并到快照。定期（30 分钟）全量兜底。
3. **身份缓存**：`getSessionUser` 结果缓存 60 秒，省掉每次 refresh 的 3 次网络往返；登录/建家/加家/改资料后失效。
4. **写穿缓存**：保存/删除事件和宝宝后立即更新快照，下次秒开就是最新的。
5. **删除即时生效**：Realtime DELETE 事件 → 界面和缓存立刻拿掉；墓碑（15 分钟）防止并发同步把已删记录写回。
6. **网络失败回退**：同步失败时保留缓存数据，不让空数据覆盖快照。

## 关键决策

- **增量用 `updated_at` 游标，不用整窗口 id 对比**：曾考虑拉窗口全量做 id 对比来发现「别人删掉的」，但那样每次还是全量传输，违背「只拉变化」。最终：删除靠 Realtime DELETE 即时处理 + 墓碑防写回 + 30 分钟全量兜底。
- **墓碑保留 15 分钟**：防止在途响应把已删记录写回；全量同步时只保留 60 秒内的墓碑（全量结果=服务端真相）。
- **快照存 localStorage 而非 IndexedDB**：数据量小（500 条事件上限），localStorage 简单可靠；空间不足时剥掉 data URL 照片降级保存。

## 影响文件

- `src/lib/cache.ts`（新增）：快照持久化、游标、墓碑、写穿辅助
- `src/lib/backend.ts`：`loadCachedData` / 增量 `loadData` / 身份缓存 / 写穿
- `src/App.tsx`：启动先渲染缓存；Realtime 删除即时处理；切换宝宝持久化
