# 2026-11-07 安卓 APK（Capacitor 壳）

## 主题

把 PWA 打包成安卓 APK，与网页版**并行可用**、数据同源，互不干扰。

## 关键决策

1. **方案**：Capacitor 8（`com.babyday.tracker`）——最贴近现有 Vite/React 代码，零重写。
2. **不冲突原则**：
   - 网页版构建 `npm run build` 原样保留（带 PWA / Service Worker）。
   - 原生构建走 `BUILD_NATIVE=1`（`npm run build:native`），**不注入 SW**——APK 更新后旧 SW 缓存会挡住新界面，这是 PWA 壳的经典坑。
   - 云端数据同一 Supabase，APK / 网页记录互通；纯本地模式各自独立（WebView 存储与浏览器隔离，正常现象）。
3. **安卓返回键**：关弹层/确认框 → 回首页 → 退出，避免误退丢未保存内容。

## 环境

本机原本无 JDK / Android SDK，首次搭建：

- JDK：Temurin 21 zip → `D:\tools\jdk-21.0.13+9`（C 盘只剩 8.9GB，工具链全部放 D 盘）
- Android SDK：cmdline-tools → `D:\android-sdk`，装 platform-tools / android-35 / android-36 / build-tools
- `android/local.properties` 指 `sdk.dir=D:\\android-sdk`
- 构建脚本 `build-apk.bat`（固化 JAVA_HOME / ANDROID_HOME）→ `gradlew -p android assembleDebug`

## 构建与发版流程

```bash
npm run android:apk     # 构建 Web（native）→ cap sync → assembleDebug
# 产物：android/app/build/outputs/apk/debug/app-debug.apk
```

web 版发版流程不变（`node scripts/release.mjs`）。

## 反思

- Gradle 首次构建下载发行版 + 依赖很慢（>15 分钟），后台跑 + 看日志比前台死等好。
- PowerShell `Start-Process` 不继承 shell 里临时设的 `JAVA_HOME`，要写 .bat 固化环境变量。
- **重复资源踩坑**：Capacitor 自带 `values/ic_launcher_background.xml`，我又建了个 `values/colors.xml` 定义同名 color → `mergeDebugResources` 报 Duplicate resources。**禁止事项**：不要自己另建 colors.xml 定义 `ic_launcher_background`，直接改 Capacitor 生成的 `ic_launcher_background.xml` 即可。
