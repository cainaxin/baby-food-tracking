# 2026-11-04 · v0.3.1 热修：所有记录保存失败

**标签**：`bug` `fix` `supabase` `schema` `photo` `save`

## 现象

v0.3.0 上线后，手机上**所有**记录（吃奶、睡觉等）保存都报错，不只是辅食。

## 原因

- `saveEvent` 把 `photo_url` 写进**每条**记录的 body（`photo_url: payload.photoUrl ?? null`）。
- Supabase `event` 表还没执行 `alter table event add column photo_url`，数据库拒绝未知字段：`Could not find the 'photo_url' column`。
- 每条保存都带此字段 → 全部失败。

## 修复（v0.3.1）

1. `photo_url` 只在真有照片时才写入 body。
2. 带照片保存若因缺列报错，降级去 `photo_url` 重试，保住记录 + toast 提示。
3. 根治：Supabase SQL Editor 执行 `alter table event add column if not exists photo_url text;`。

## 反思

- **禁止**：假设数据库列已存在就把新字段无条件写进 insert/update body。先兼容、后迁移。
- 新加数据库字段时，前端必须做「字段缺失降级」，否则未迁移的库会全挂。
- schema.sql 改了 ≠ 用户的库已迁移；发布新字段前要么提示用户先跑迁移，要么代码自动兼容。

## 禁止事项

- ❌ 给已有表加字段后，前端**无条件**把新字段写进每条记录的 body。
- ❌ 只改 schema.sql 不验证用户库是否已迁移，就当功能可用。
