## 事故：主路由 Docker + firewall 导致断网

**标签**：`failure` `docker` `iptables` `firewall` `outage` `openwrt`

### 现象

- 部署过程中家里网全断；与「关闭 TTYD 网页」无关（时间巧合）。

### 直接原因（操作）

```sh
docker run -p 3006:80 ...     # Docker 为端口映射改写 iptables
/etc/init.d/firewall restart # 与 Docker 规则冲突，NAT/转发损坏
```

### 根因（决策错误）

1. **在 iStoreOS 主路由上**使用会改 iptables 的 Docker 端口映射（`-p`）。
2. Docker 生效后又 **restart 防火墙**，fw3/fw4 与 docker 规则叠加破坏。
3. 未评估主路由风险就把「应用部署」和「家用网关」耦在同一台机器的网络栈上。

### 恢复

```sh
docker stop baby-web && docker rm -f baby-web
/etc/init.d/docker stop
/etc/init.d/firewall restart
/etc/init.d/network restart
# 仍不行：断电重启软路由
```

### 反思

- **网关上网络稳定 > 上新服务**；应用端口暴露不能以牺牲全家网为代价。
- 改防火墙/装 Docker 前先想：失败时是否还能远程进入？是否需要有人在现场？
- 断网类事故恢复优先于继续部署；恢复后先验证上网，再考虑站点。

### 禁止事项（今后）

- ❌ 在主路由上 `docker run -p ...`（DNAT/改 iptables）而不做隔离评估。
- ❌ Docker 运行中随意 `firewall restart`。
- ❌ 未确认远程回滚路径就动网关防火墙。

### 正确方向（阶段二预告）

- 服务放旁路（NAS/其他主机），主路由只做端口转发；或  
- `network_mode: host` + 仅增加单端口 ACCEPT，避免 Docker 接管 NAT；或  
- 不经 Docker，用独立端口的轻量静态服务，并一次只改一处。
